# 票据匹配策略 - 用户友好配置指南

## 🎯 配置目标

基于用户反馈，我们优化了票据匹配策略的配置方式，让用户能够**简单直观**地配置票据匹配逻辑。

### 主要优化

1. **简化配置**：用户只需配置指定字段即可
2. **顺序匹配简化**：配置为空或`["_position"]`即可启用顺序匹配  
3. **预设优化**：预设文档类型有智能默认配置，自定义类型默认顺序匹配

---

## 📋 用户配置方式

### 方式1: 通过界面配置

在项目设置的"评估字段配置"页面：

```
┌─────────────────────────────────────┐
│ 票据匹配策略                        │
├─────────────────────────────────────┤
│ □ 使用顺序匹配（按位置一对一配对）  │
│                                     │
│ 🎯 字段匹配                         │
│ 当前文档类型：银行回单              │
│ 预设主键字段：recieptNum, amount    │
│                                     │
│ 主键字段配置：                      │
│ [recieptNum] [×] [amount] [×]       │
│ [+ 添加字段]                        │
│                                     │
│ 配置预览：                          │
│ 字段匹配：主键 [recieptNum, amount] │
└─────────────────────────────────────┘
```

### 方式2: 通过API配置

```python
# 1. 使用预设配置（推荐）
config = {
    "type": "degraded_field_based",
    "mode": "field_based", 
    "primary_fields": ["recieptNum", "amount"],  # 银行回单预设
    "verbose": True
}

# 2. 使用顺序匹配
config = {
    "type": "degraded_field_based",
    "mode": "field_based",
    "primary_fields": [],  # 空配置 = 顺序匹配
    "verbose": True
}

# 3. 自定义字段匹配
config = {
    "type": "degraded_field_based", 
    "mode": "field_based",
    "primary_fields": ["docType", "invoiceDate", "totalAmount"],
    "verbose": True
}
```

## 🏭 预设文档类型配置

我们为常见文档类型提供了智能预设配置：

| 文档类型 | 预设主键字段 | 适用场景 | 
|---------|-------------|----------|
| **发票** (invoice) | `["docType", "totalAmount"]` | 发票验证，基于类型和金额匹配 |
| **银行回单** (bank_receipt) | `["recieptNum", "amount"]` | 银行回单验证，基于回单号和金额 |
| **收据** (receipt) | `["receiptNumber", "totalAmount"]` | 收据验证，基于收据号和金额 |
| **自定义** (custom) | `[]` (顺序匹配) | 灵活场景，默认按位置匹配 |

### 预设配置的智能降级

每个预设配置都支持自动降级匹配：

```
银行回单示例：
1️⃣ 尝试双字段匹配：["recieptNum", "amount"] 
2️⃣ 降级到单字段：["amount"]
3️⃣ 最后回退到位置匹配：["_position"]
```

## 👤 用户交互场景

### 场景1: 银行回单批量处理 ✅

**需求**：处理100张银行回单，需要按回单号精确匹配

**用户操作**：
1. 选择"银行回单"文档类型
2. 系统自动配置：`["recieptNum", "amount"]`
3. 确认配置

**结果**：字段匹配，主键自动降级：回单号+金额 → 金额 → 位置

### 场景2: 银行流水顺序处理 ✅

**需求**：银行流水数据，标准与预测顺序一致，需要快速处理

**用户操作**：
1. 选择任意文档类型
2. 勾选"使用顺序匹配"
3. 确认配置

**结果**：顺序匹配，第1张标准对应第1张预测，第2张对应第2张

### 场景3: 发票智能匹配 ✅

**需求**：混合发票类型，需要包含日期进行精确匹配

**用户操作**：
1. 选择"发票"文档类型（预设：`docType, totalAmount`）
2. 点击"添加字段"，添加`invoiceDate`
3. 最终配置：`["docType", "totalAmount", "invoiceDate"]`

**结果**：智能降级匹配，从3字段逐步降级到1字段

### 场景4: 简单收据处理 ✅  

**需求**：收据号码唯一，只需要基于收据号匹配

**用户操作**：
1. 选择"收据"文档类型（预设：`receiptNumber, totalAmount`）
2. 删除`totalAmount`字段，只保留`receiptNumber`
3. 最终配置：`["receiptNumber"]`

**结果**：单字段匹配，极简配置

## 🔧 配置规则详解

### 核心规则

1. **空配置 = 顺序匹配**
   ```python
   primary_fields: []  # 使用顺序匹配
   primary_fields: ["_position"]  # 显式指定顺序匹配
   ```

2. **指定字段 = 字段匹配**
   ```python
   primary_fields: ["recieptNum"]  # 单字段匹配
   primary_fields: ["recieptNum", "amount"]  # 多字段降级匹配
   ```

3. **无效字段 = 自动回退**
   ```python
   primary_fields: ["不存在的字段"]  # 自动回退到顺序匹配
   ```

### 智能降级逻辑

配置 `["A", "B", "C"]` 的降级路径：
```
1️⃣ 尝试: ["A", "B", "C"] (完整匹配)
2️⃣ 降级: ["B", "C"] (部分匹配)  
3️⃣ 降级: ["C"] (最小匹配)
4️⃣ 回退: ["_position"] (位置匹配)
```

## 🚀 最佳实践建议

### 1. 选择合适的文档类型
- 有固定格式的票据（发票、回单） → 选择对应预设类型
- 灵活格式或测试场景 → 选择"自定义"类型

### 2. 确定匹配策略
- 有唯一标识字段（票据号、发票号） → 使用字段匹配
- 顺序一致的批量数据 → 使用顺序匹配  

### 3. 字段选择原则
- **优先选择**：唯一性强的字段（票据号码、ID）
- **其次选择**：重要业务字段（金额、日期）
- **避免选择**：容易重复的字段（名称、描述）

### 4. 配置验证
- 使用"配置预览"功能确认最终策略
- 在小批量数据上先测试效果
- 根据实际匹配结果调整配置
