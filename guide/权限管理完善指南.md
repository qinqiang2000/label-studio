# Label Studio 权限管理完善指南

## 文档概述

本文档提供Label Studio项目中Projects和Prompts模块权限管理的完善方案，包含现状分析、问题诊断、技术方案和详细实施步骤。旨在实现细粒度的权限控制，提升系统安全性和用户体验。

**编写时间**: 2025-08-04  
**适用版本**: Label Studio 1.20.0.dev0  
**实施预估**: 4-6小时  

---

## 1. 现状分析

### 1.1 当前权限架构

Label Studio采用基于角色的权限控制系统（RBAC），包含以下层次：

```
权限系统架构
├── 菜单权限 (menu) - 15个
├── 操作权限 (action) - 14个  
├── 页面操作权限 (page_operation) - 10个
├── 字段权限 (field_permission) - 5个
└── 管理权限 (admin) - 4个
```

### 1.2 Projects模块权限现状

**定义的权限（22个）**：
```python
# 菜单权限 (9个)
view_projects, view_project_general_settings, view_project_labeling_settings,
view_project_annotation_settings, view_project_machine_learning, 
view_project_predictions, view_project_cloud_storage, view_project_webhooks,
view_project_danger_zone

# 操作权限 (5个) 
create_project, edit_project, delete_project, export_project_data, import_project_data

# 页面操作权限 (4个)
show_create_project_button, show_import_project_button, 
show_export_project_button, show_delete_project_button

# 字段权限 (3个)
edit_project_danger_zone_fields, edit_project_ml_settings, edit_project_webhook_settings
```

**实际使用的权限（仅4个）**：
- `projects.create` - 创建项目
- `projects.view` - 查看项目  
- `projects.change` - 修改项目
- `projects.delete` - 删除项目

**问题诊断**：
1. **前后端权限脱节**：前端定义了22个细粒度权限，后端只实现4个基础权限
2. **权限检查简化**：Project模型的`has_permission()`方法只是返回True的stub
3. **功能与权限未关联**：大部分前端权限配置未与实际功能关联

### 1.3 Prompts模块权限现状

**定义的权限（1个）**：
- `view_prompts` - Prompts菜单查看

**实际使用**：
- 通过通用装饰器`@module_permission_required('prompts')`实现基础访问控制

**问题诊断**：
1. **权限过于粗粒度**：只能"全有"或"全无"，无法精细控制
2. **缺少操作权限**：无create、edit、delete等操作级权限
3. **扩展性不足**：难以适应复杂的权限需求

## 2. 技术方案设计

### 2.1 设计原则

1. **统一性**：Projects和Prompts采用相同的权限模式
2. **细粒度**：支持菜单、操作、页面、字段四个层次的权限控制
3. **兼容性**：保持现有功能不受影响
4. **扩展性**：为其他模块提供可复用的权限模式

### 2.2 权限分层设计

```
模块权限分层
├── 访问权限 (view_module) - 控制模块访问
├── 操作权限 (action) - 控制CRUD操作
├── 页面权限 (page_operation) - 控制按钮显示
└── 字段权限 (field_permission) - 控制字段编辑
```

### 2.3 权限包设计

为简化权限管理，设计三层权限包：

```python
权限包层次
├── basic_access - 基础访问（查看）
├── management - 管理权限（创建、编辑）  
└── full_access - 完整权限（包含删除）
```

## 3. Projects模块完善方案

### 3.1 后端API权限完善

#### 3.1.1 更新Project模型权限检查

**文件**: `label_studio/projects/models.py`

**当前代码**：
```python
def has_permission(self, user):
    """Dummy stub for has_permission"""
    user.project = self  # link for activity log
    return True
```

**修改为**：
```python
def has_permission(self, user):
    """检查用户对项目的权限"""
    user.project = self  # link for activity log
    
    # 超级用户拥有所有权限
    if user.is_superuser:
        return True
        
    # 检查用户是否是项目所属工作空间的成员
    if self.workspace and not self.workspace.has_member(user):
        return False
        
    # 基础查看权限检查
    return user.has_perm('projects.view')

def can_create_project(self, user):
    """检查用户是否可以创建项目"""
    return user.has_perm('projects.create')
    
def can_edit_project(self, user):
    """检查用户是否可以编辑项目"""
    return user.has_perm('projects.change') and self.has_permission(user)
    
def can_delete_project(self, user):
    """检查用户是否可以删除项目"""
    return user.has_perm('projects.delete') and self.has_permission(user)
```

#### 3.1.2 创建详细权限类

**文件**: `label_studio/projects/permissions.py`

**新增代码**：
```python
from rest_framework import permissions
from django.contrib.auth.models import Permission

class ProjectDetailPermission(permissions.BasePermission):
    """项目详细操作权限检查"""
    
    def has_permission(self, request, view):
        if request.user.is_superuser:
            return True
            
        method_permission_map = {
            'GET': 'view_projects',
            'POST': 'create_project', 
            'PUT': 'edit_project',
            'PATCH': 'edit_project',
            'DELETE': 'delete_project',
        }
        
        required_permission = method_permission_map.get(request.method)
        if required_permission:
            return request.user.has_perm(required_permission)
        return False
        
    def has_object_permission(self, request, view, obj):
        return obj.has_permission(request.user)

class ProjectSettingsPermission(permissions.BasePermission):
    """项目设置页面权限检查"""
    
    SETTINGS_PERMISSION_MAP = {
        'general': 'view_project_general_settings',
        'labeling': 'view_project_labeling_settings', 
        'annotation': 'view_project_annotation_settings',
        'machine_learning': 'view_project_machine_learning',
        'predictions': 'view_project_predictions',
        'cloud_storage': 'view_project_cloud_storage',
        'webhooks': 'view_project_webhooks',
        'danger_zone': 'view_project_danger_zone',
    }
    
    def has_permission(self, request, view):
        if request.user.is_superuser:
            return True
            
        # 从URL或参数中获取设置类型
        settings_type = request.GET.get('tab') or getattr(view, 'settings_type', 'general')
        required_permission = self.SETTINGS_PERMISSION_MAP.get(settings_type)
        
        if required_permission:
            return request.user.has_perm(required_permission)
        return False
```

### 4.2 API权限细化

#### 4.2.1 升级权限类

**文件**: `label_studio/prompts/permissions.py`

**替换现有代码**：
```python
from rest_framework import permissions

class PromptsPermission(permissions.BasePermission):
    """Prompts模块细粒度权限检查"""
    
    def has_permission(self, request, view):
        if request.user.is_superuser:
            return True
            
        # 根据HTTP方法检查不同权限
        method_permission_map = {
            'GET': 'view_prompts',
            'POST': 'create_prompts',
            'PUT': 'edit_prompts', 
            'PATCH': 'edit_prompts',
            'DELETE': 'delete_prompts',
        }
        
        required_permission = method_permission_map.get(request.method)
        if required_permission:
            return request.user.has_perm(required_permission)
        return False
        
    def has_object_permission(self, request, view, obj):
        """对象级权限检查"""
        if request.user.is_superuser:
            return True
            
        # 检查workspace权限
        if obj.workspace and not obj.workspace.has_member(request.user):
            return False
            
        # 检查是否为创建者或有相应权限
        if obj.created_by == request.user:
            return True
            
        method_permission_map = {
            'GET': 'view_prompts',
            'PUT': 'edit_prompts',
            'PATCH': 'edit_prompts', 
            'DELETE': 'delete_prompts',
        }
        
        required_permission = method_permission_map.get(request.method)
        return request.user.has_perm(required_permission) if required_permission else False

class PromptsAccessPermission(permissions.BasePermission):
    """Prompts模块访问权限检查 - 向后兼容"""
    
    def has_permission(self, request, view):
        if request.user.is_superuser:
            return True
        return request.user.has_perm('view_prompts')
```

5. **前端配置**: 在`permissions.js`中添加权限包配置
6. **测试验证**: 编写测试用例验证权限功能

### 7.2 权限包管理最佳实践

#### 7.2.1 权限包命名规范
```
{module}_{level}_access
- module: 模块名（如project、prompts）
- level: 权限级别（basic、management、full）
- access: 固定后缀
```

#### 7.2.2 权限层次设计
```
基础层: 查看权限
├── view_{module}
├── view_{module}_settings

管理层: 操作权限  
├── create_{module}
├── edit_{module}  
├── show_{operation}_button

完整层: 危险权限
├── delete_{module}
├── export_{module}
└── import_{module}
```
