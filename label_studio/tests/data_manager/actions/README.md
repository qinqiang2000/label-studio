## 使用方法

### 1. 快速开始
```bash
# 进入label_studio目录
cd /path/to/label-studio/label_studio

# 准备测试环境
python manage.py shell -c "
from projects.models import Project
from evaluation_configs.models import EvaluationFieldConfig, ProjectEvaluationConfig

# 确保测试项目配置正确
project1 = Project.objects.get(id=1)
invoice_config = EvaluationFieldConfig.objects.get(key='invoice')
project_config, created = ProjectEvaluationConfig.objects.get_or_create(
    project=project1,
    defaults={'evaluation_config': invoice_config}
)
print('测试环境准备完成')
"

# 启动Label Studio服务
python manage.py runserver 127.0.0.1:8080
```

### 2. 执行基础测试
参考 `evaluation_test_runner.md` 中的具体步骤：

1. **手动测试**: 按照测试用例文档逐步执行
2. **Playwright自动化**: 使用MCP Playwright工具执行UI测试
3. **API测试**: 直接调用后端API进行功能验证

## 测试历史背景

### 解决的历史问题
在开发过程中，我们遇到并解决了以下关键问题：

1. **界面卡死问题**
   - **问题**: 评估对话框导致界面冻结
   - **原因**: 复杂的表单渲染逻辑
   - **解决**: 简化对话框内容，移除配置选择下拉框

2. **API参数错误**
   - **问题**: project参数传递None导致API调用失败
   - **原因**: 前端参数传递逻辑错误
   - **解决**: 确保表单参数正确传递给API

3. **总字段数为0**
   - **问题**: 评估结果显示总字段数为0
   - **原因**: 文档类型验证规则不匹配实际数据
   - **解决**: 修正验证规则，允许正确的文档类型

4. **配置不匹配**
   - **问题**: 项目使用的配置与数据类型不匹配
   - **原因**: 默认配置分配逻辑问题
   - **解决**: 为项目设置正确的评估配置

### 测试用例设计原则
基于这些历史问题，我们的测试用例设计遵循以下原则：

- **覆盖真实场景**: 每个测试用例都基于实际遇到的问题
- **边界条件验证**: 测试极端情况和异常输入
- **回归防护**: 确保修复的问题不再出现
- **用户体验**: 验证界面友好性和操作流畅性
