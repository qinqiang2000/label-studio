# 文档提取评估功能测试用例

## 概述
本文档包含文档提取评估功能的详细测试用例，涵盖正常流程、异常情况和边界测试。所有测试用例都以自然语言描述，可以通过Playwright或其他工具执行。

## 测试环境准备
- 确保Label Studio服务运行在 http://127.0.0.1:8080
- 准备多个测试项目，包含不同的评估配置
- 确保测试数据包含annotation和prediction数据

---

## 1. 基础功能测试

### 1.1 评估对话框显示测试
**测试目的**: 验证评估对话框正确显示简化后的内容

**测试步骤**:
1. 导航到项目数据页面 (例如: http://127.0.0.1:8080/projects/1/data?tab=9)
2. 选择一个或多个任务
3. 点击任务数量按钮 (如 "1 Task")
4. 点击 "Evaluate Document Extraction" 选项

**预期结果**:
- 对话框正常显示，不出现卡死现象
- 显示简化的提示文本: "This evaluation will compare annotation and prediction results for accuracy. If multiple versions exist, the latest will be used. The evaluation will use the current project configuration. To change evaluation fields, configure them in Project Settings > General Settings."
- 没有配置选择下拉框
- 显示 OK 和 Cancel 按钮

### 1.2 评估执行成功测试
**测试目的**: 验证评估功能正常执行并返回正确结果

**测试步骤**:
1. 在评估对话框中点击 OK 按钮
2. 等待评估完成
3. 检查评估结果页面

**预期结果**:
- 评估成功完成，没有错误
- 显示正确的统计信息:
  - 总文档数 > 0
  - 总票据数 > 0
  - 总字段数 > 0 (关键指标)
- 显示使用的模型名称
- 显示整体准确率
- 每个字段都有具体的准确率数据

### 1.3 Excel报告下载测试
**测试目的**: 验证Excel报告生成和下载功能

**测试步骤**:
1. 在评估结果页面点击 "Download Excel" 按钮
2. 检查浏览器下载

**预期结果**:
- Excel文件成功下载
- 文件包含详细的评估数据
- 没有出现错误提示

## 2. 配置匹配测试

### 2.1 Invoice配置项目测试
**测试目的**: 验证使用Invoice配置的项目评估正常

**测试数据**: 项目包含docType为'invoice'的数据
**评估配置**: Invoice配置 (允许 ['invoice', 'receipt'])

**测试步骤**:
1. 确认项目使用Invoice配置
2. 执行评估
3. 检查结果

**预期结果**:
- 总字段数正确显示 (通常为6个字段: billFromName, billToName, currency, docType, invoiceDate, totalAmount)
- 所有文档都被正确处理
- 没有因文档类型不匹配而跳过文档

### 2.2 Custom配置项目测试
**测试目的**: 验证使用Custom配置的项目评估正常

**测试数据**: 项目包含docType为'invoice'的数据
**评估配置**: Custom配置 (允许 ['invoice', 'custom'])

**测试步骤**:
1. 确认项目使用Custom配置
2. 执行评估
3. 检查结果

**预期结果**:
- 总字段数正确显示 (通常为7个字段: 包含自定义字段如billFromName)
- 所有文档都被正确处理
- 自定义字段正确参与评估

### 2.3 Bank Receipt配置项目测试
**测试目的**: 验证Bank Receipt配置的兼容性

**测试数据**: 项目包含docType为'bank_receipt'的数据
**评估配置**: Bank Receipt配置 (允许 ['bank_receipt'])

**测试步骤**:
1. 确认项目使用Bank Receipt配置
2. 确认数据包含正确的docType
3. 执行评估

**预期结果**:
- 评估正常执行
- 总字段数正确显示
- 银行收据特定字段正确评估

## 3. 异常情况测试

### 3.1 文档类型不匹配测试
**测试目的**: 验证文档类型与配置不匹配时的处理

**测试场景**:
- 场景A: Bank Receipt配置 + invoice类型数据
- 场景B: Invoice配置 + bank_receipt类型数据
- 场景C: Custom配置 + 不允许的文档类型

**测试步骤**:
1. 设置项目使用特定配置
2. 确保数据包含不匹配的docType
3. 执行评估

**预期结果**:
- 总字段数显示为0 (因为所有文档被跳过)
- 或者显示适当的错误信息
- 系统不应该崩溃

### 3.2 空数据集测试
**测试目的**: 验证没有数据时的处理

**测试步骤**:
1. 选择没有annotation或prediction数据的任务
2. 执行评估

**预期结果**:
- 显示适当的提示信息
- 总字段数为0
- 不出现系统错误

### 3.3 API参数错误测试
**测试目的**: 验证API参数传递错误时的处理

**测试场景**:
- project参数为None
- 无效的任务ID
- 缺少必要参数

**测试方法**: 通过浏览器开发者工具监控网络请求，或直接调用API

**预期结果**:
- 返回适当的错误信息
- 不导致系统崩溃
- 错误信息对用户友好

## 6. 安全性测试

### 6.1 权限验证测试
**测试目的**: 验证用户权限控制

**测试步骤**:
1. 使用不同权限级别的用户
2. 尝试访问不同项目的评估功能

- 无权限用户无法执行评估

### 6.2 数据隔离测试
**测试目的**: 验证项目间数据隔离

**测试步骤**:
1. 在项目A中执行评估
2. 检查是否只处理项目A的数据
3. 验证不会访问其他项目数据

**预期结果**:
- 严格的数据隔离
- 只评估当前项目的任务
- 不泄露其他项目信息

## 7. 性能测试

### 7.1 响应时间测试
**测试目的**: 验证评估功能的响应时间

**测试数据**: 不同规模的数据集 (1, 10, 50, 100个任务)
**测试步骤**:
1. 记录评估开始时间
2. 等待评估完成
3. 记录总耗时

**预期结果**:
- 小数据集 (<10任务): <5秒
- 中等数据集 (10-50任务): <30秒
- 大数据集 (50+任务): <2分钟

### 7.2 并发测试
**测试目的**: 验证多用户同时评估的处理

**测试步骤**:
1. 多个用户同时在不同项目执行评估
2. 监控系统资源使用
3. 检查评估结果的正确性

**预期结果**:
- 系统稳定运行
- 所有评估都正确完成
- 资源使用在合理范围内

## 8. 回归测试

### 8.1 历史问题回归测试
**测试目的**: 验证之前修复的问题不再出现

**历史问题列表**:
1. **界面卡死问题**: 评估对话框导致界面冻结
2. **project参数None错误**: API调用时project参数传递None
3. **总字段数为0问题**: 文档类型不匹配导致字段数显示为0
4. **Excel下载失败**: 报告生成和下载功能异常

**测试步骤**:
1. 重现每个历史问题的场景
2. 执行相应操作
3. 验证问题已修复

**预期结果**:
- 所有历史问题都已解决
- 相关功能正常工作
- 没有新的回归问题

### 8.2 配置变更影响测试
**测试目的**: 验证评估配置变更后的影响

**测试步骤**:
1. 记录项目当前评估结果
2. 修改项目评估配置
3. 重新执行评估
4. 对比结果差异

**预期结果**:
- 配置变更正确反映在评估中
- 新配置的字段正确参与评估
- 旧配置的字段正确排除

## 测试执行顺序建议

1. **第一阶段**: 基础功能测试 (确保核心功能正常)
2. **第二阶段**: 配置匹配测试 (验证不同配置的兼容性)
3. **第三阶段**: 异常情况测试 (验证错误处理)
4. **第四阶段**: 边界条件测试 (验证极端情况)
5. **第五阶段**: 性能和安全测试 (验证非功能性需求)
6. **第六阶段**: 回归和集成测试 (确保整体稳定性)

## 测试通过标准

- **功能性**: 所有基础功能正常工作
- **准确性**: 评估结果数据正确
- **稳定性**: 没有系统崩溃或卡死
- **性能**: 响应时间在可接受范围内
- **用户体验**: 界面友好，操作流畅
- **错误处理**: 异常情况有适当提示
- **数据安全**: 权限控制和数据隔离有效
