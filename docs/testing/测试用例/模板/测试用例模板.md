## 编写指南

### 测试用例编号规则
- **TC-USXXX**：对应用户故事US-XXX的测试用例
- **TC-USXXX-Y**：同一用户故事的第Y个测试用例
- **TC-USXXX-边界**：边界值测试用例
- **TC-USXXX-异常**：异常场景测试用例

### 测试场景设计原则
1. **完整覆盖**：确保所有验收标准都有对应的测试场景
2. **独立性**：每个测试场景应该独立可执行
3. **可重复性**：测试结果应该是可重复的
4. **清晰性**：测试步骤应该清晰明确，便于执行

### 测试数据管理
- 使用真实但脱敏的数据
- 准备边界值和异常值数据
- 确保测试数据的一致性和完整性
- 测试完成后及时清理测试数据

### BDD格式说明
- **Given**：描述测试的前置条件和初始状态
- **When**：描述用户的操作或触发的事件
- **Then**：描述期望的结果和系统状态

### 测试结果判定标准
- **通过**：所有测试步骤执行成功，实际结果与期望结果一致
- **失败**：测试步骤执行失败或实际结果与期望结果不一致
- **阻塞**：由于环境或依赖问题无法执行测试
- **跳过**：由于某些条件不满足而跳过的测试
